# Pi commit-provenance capabilities

Authority: `devspec://product/implementation-contract` → `commit_provenance_contract`

Pi provenance support is cooperative assistance, not a filesystem, shell, or Git sandbox. Unsupported and ambiguous surfaces use instructions plus DevSpec's universal commit ingestion/analyzer.

| Surface | What Pi honestly receives | Safe transformation | Behavior |
|---|---|---:|---|
| First-class file edits (`write`, `edit`, `apply_patch`, `notebook`) | Tool name and structured arguments before execution | None needed | After positive project jurisdiction from an explicit pin or uniquely server-verified credential-free remote, and with no observed claim for that project, inject at most one non-blocking nudge per Pi session/project. Remote results are endpoint/token/repo/pin-isolated and TTL-cached; every auth/network/ambiguous state emits nothing. Always allow the edit. |
| Arbitrary Bash/shell | Structured Pi tool lifecycle plus the model-authored command. The command text is never parsed for provenance policy. | For model `bash` only, prepend a private session PATH entry through Pi's mutable `tool_call` input; this does not inspect the original command or replace Bash. | Never classify for mutation authority or block. The private Git shim delegates exact argv/stdin/stdout/stderr/exit status, forwards common termination signals, and fails open on every unsupported/error state. User `!` Bash is not instrumented. |
| Direct Git commit | No first-class Pi commit hook. The private session Git argv shim receives ordinary `git` process argv/cwd, keeps Trace2 memory-only over a private Unix socket, and proves a successful direct `commit` against the actual primary worktree and HEAD reflog. | No pre-commit rewrite/stamp. Record a full post-commit SHA/message/branch in the in-process ledger and queue a `plugin_observed` measurement with identity frozen before Bash execution. | Covers normal/root/quiet/amend/alias, `git -C`, shell `cd`, linked worktrees and multi-repo compound Bash. Never deny; reporting is bounded, reload-safe, best-effort and grants no authority. Current summary-output capture remains fallback. |
| Git rewrite/ref operations | Trace2 identifies the command family/repository but does not itself provide stable created-OID/ref-transaction evidence. | None until newly-created commit causality is mechanically proved. | `merge`, `cherry-pick`, `revert`, `rebase`, `am`, `update-ref`, `commit-tree`, fetch/fast-forward remain candidate/unknown and rely on universal ingestion/analyser recovery; they are never attributed by guess. |
| Git push/outgoing history | No first-class outgoing-commit set or push-policy hook | None | Never deny. Instructions plus server ingestion/analyzer provide recovery. Ambiguous history and service outages fail open. |
| Project association | Existing pin can be read; `/devspec.pin <full-project-uuid>` is an explicit local command | Explicit command may create/refresh the repository-root pin | Generic login, connection, bond, and remote delivery never write the current folder. Missing/malformed/unreadable pins are non-blocking. |
| DevSpec unavailable | Transport/auth/resource errors | None | Local edits, execution, tests, worktrees, cross-repository work, delegation, commits, and pushes continue. The v4 local fallback preserves coordination and linkage guidance without becoming a gate. |
| Post-implementation tools | Native DevSpec result and structured arguments | Host may mechanically attach a ledger SHA/message/source report | `record_implementation`, evidence, criterion verdicts, testing, release, and failure follow-through are never gated by claim state in Pi. |
| Exact-connection commit review notice | Strict canonical remote-ingress 1.4 notice v1, addressed to the frozen Pi bond | Capacity-gate claims, queue only in bounded generation-scoped memory while busy, and start a fresh activity-neutral custom harness turn when idle | The model is pointed to `devspec://product/remote-ingress-contract` and `devspec://product/implementation-contract`; notice text creates no command or commit provenance. |
| Subagents/unattended work | Ordinary Pi/provider behavior; no provenance-grade inherited authority signal | None | No trusted-child exception or lease. Parent and child work continue; commit linkage and server reconciliation remain authoritative. |

Pi observes ordinary direct commits made through model Bash without model compliance, including quiet and alternate-repository forms. The shim's child-written journal is never trusted alone: the host independently requires current HEAD, reflog action/time, commit time, and root/normal/amend parent topology to match the pre-execution envelope; concurrent or hook-moved HEAD fails open. This is same-user operational measurement, not hostile-process attestation, and grants no authority.

Pi still does **not** claim universal process coverage: human `!` Bash, external IDE/terminal Git, absolute Git paths bypassing PATH, libgit2/JGit/Dulwich, unbonded inherited children, and ambiguous history rewrites remain unknown rather than guessed. Universal ingestion/analyser recovery remains required.

Independent DevSpec authentication/authorization, destructive database safeguards, cost confirmation, provider permissions, and Pi's own host controls are unchanged.
